# GYH 主页面重设计规格

日期：2026-08-30

## 1. 目标

彻底替换当前主页的视觉结构，建立一个以超近景黑色笔记本为唯一界面的固定单屏体验。设计继承用户提供的 404 笔记本参考图所体现的视觉逻辑：设备大幅裁切、屏幕与外部背景同色融合、底部机身压入前景、巨型背景字承载构图、中央真实影像作为视觉主体、界面元素极少。

主页继续连接五个现有专题路由，但场景内容以用户提供的五张照片为最终依据，不再沿用旧主页中的程序化插画场景。

## 2. 最终主题与素材映射

主题顺序固定为：

1. `F1` → `/racing`
2. `M4` → `/cars`
3. `COLNAGO` → `/bikes`
4. `FISH` → `/aqua`
5. `PHOTO` → `/photo`

用户提供的源文件只用于一次性素材导入：

- `d83f4bb681e32334d882f9184effc729.jpg` → `f1.jpg`
- `bdc1354781efd7646f5522d5317e180d.jpg` → `m4.jpg`
- `b26a33c6743bfc579c103c2ab41d2756.jpg` → `colnago.jpg`
- `ab691baef3ef1ac426eaa7fd2382b25b.jpg` → `fish.jpg`
- `adbd8cfc420affebc8d38fb328312787.jpg` → `photo.jpg`

正式实现必须把源图复制到项目内的 `src/assets/home/`，生成语义化文件名，并通过 Vite 静态导入使用。运行时代码、CSS、配置和构建产物不得引用 `C:\Users\24939\Desktop\1111`、Codex 临时目录或任何其他本机绝对路径。桌面源文件夹删除后，项目仍必须能独立开发、构建和部署。

可在 `src/assets/home/derived/` 保存为网页生成的 WebP、遮罩或低分辨率预载版本。所有衍生资源也必须进入项目，不依赖外部 URL。

### 2.1 部署前图像增强

是否需要超分必须依据实际像素尺寸、压缩伪影和最终显示尺寸判断，不能只依据文件体积。当前五张源图的检查结果为：

- `FISH`：2800 × 1446，约 4.05MP。
- `PHOTO`：6048 × 3402，约 20.58MP。
- `COLNAGO`：1368 × 726，约 0.99MP。
- `M4`：2800 × 1170，约 3.28MP。
- `F1`：1440 × 716，约 1.03MP。

默认处理策略：

- `F1` 和 `COLNAGO` 在进入网页素材管线前执行 2× 超分，目标尺寸分别约为 2880 × 1432 和 2736 × 1452。
- `M4` 与 `FISH` 不因文件小于 1MB 而自动放大；先检查 JPEG 块效应、边缘振铃和局部锐度，只在确有问题时执行去噪、去块或轻量细节恢复。
- `PHOTO` 不做超分，只生成适合网页加载的响应式衍生版本。
- 原始照片保存在项目资产目录中作为无损对照，超分和修复结果写入 `src/assets/home/derived/`，不得覆盖唯一原件。
- 超分不得改变赛车、车辆、自行车、车手、鱼类、建筑轮廓、品牌标识或文字内容。重点检查车标、轮辐、头盔、人物五官、鱼体边缘和塔身灯光，拒绝虚构结构、重影、塑料质感、过度锐化和光晕。
- 最终网页使用超分或修复后的衍生图，并继续生成适合不同视口和 DPR 的较小响应式版本，避免把最大尺寸文件无条件传给所有设备。

## 3. 视觉骨架

### 3.1 固定单屏舞台

主页为 `position: fixed` 的全视口舞台，不参与 Lenis 长页面滚动。浅灰颗粒台面位于底部，哑光主题背景覆盖其余区域。页面捕获滚轮和触控手势，用于主题选择。

### 3.2 笔记本空间模型

采用已确认的 A「参考图锁定」构图：

- 黑色笔记本占据绝大部分视口，顶部和左右边框可见，部分机身超出画面。
- 基础姿态约为 `rotateY(-7deg) rotateX(2deg)`，设备向左偏转并轻微后仰。
- 屏幕内容、边框和底部机身必须处于同一 3D 坐标系，使用共享透视矩阵；不能只倾斜外壳而保留正面屏幕贴图。
- 鼠标位置只附加不超过 `1.5deg` 的轻微视差。
- 设备底部接触点、台面和接触阴影保持稳定，不使用悬浮、呼吸或上下漂移动画。
- 屏幕内所有交互元素必须留在透视后的安全区中，避免右侧 Option Wheel 被裁切。

### 3.3 屏幕内容层级

从后到前依次为：

1. 当前主题的照片主色底层。
2. 巨型半透明背景字：`F1 / M4 / COLNAGO / FISH / PHOTO`。
3. 真实照片及其分层动态效果。
4. 左上角静态个人标签 `GYH`。
5. 右侧 React Bits `OptionWheel`。
6. 中央下方 React Bits `SpecularButton`。
7. 克制的屏幕玻璃反射与边缘暗角。

不保留顶部五个专题标签，不保留 `MENU`，屏幕外不显示全站导航。

### 3.4 背景融合

屏幕外不延伸真实照片。每个主题从对应照片提取一组哑光主色，叠加低对比细颗粒。主题滚动时，背景色在相邻主题之间连续插值。黑色屏幕边框负责区分真实照片与外部平面，同时维持参考图的同色融合感。

## 4. 主题动态设计

所有动态必须建立在真实照片已有内容与合理物理运动之上。禁止卡通化拉伸、无依据的物体变形或与原图冲突的特效。

### 4.1 F1

- 将原图烟雾拆分为前、中、后三层，采用不同速度和透明度扩散。
- 赛车只做轻微悬挂震动与高频机械振动。
- 地面局部加入热浪折射，观众席加入低频、不规则闪光灯。
- 进入或离开主题时，烟雾可作为自然遮挡层承接相邻画面。

### 4.2 M4

- 保持黄色 M4 正面主体与原有镜头关系。
- 前轮旋转并产生小幅转向角变化；车身按悬挂受力轻微侧倾和回正。
- 道路和远处背景产生横向速度差与运动模糊。
- 车漆高光沿引擎盖缓慢扫过。
- 不添加原图没有物理依据的夸张胎烟。

### 4.3 COLNAGO

- 保持 UAE 车手、Colnago 计时车和雪山背景关系。
- 前景草叶快速视差，中景树林缓慢位移，雪山近乎静止。
- 车轮高速旋转；车手、衣料与车架只产生细微路面震动。
- 运动层级应符合长焦镜头的空间压缩感。

### 4.4 FISH

- 保留沉木、水草、底床和鱼群构图。
- 水面焦散缓慢移动，水中悬浮颗粒具有前后景速度差和景深。
- 水草只做低频摆动。
- 鱼群在有限路径内游动，前景鱼略快、远景鱼略慢。
- 不以整张图片缩放代替水下运动。

### 4.5 PHOTO

- 将城市夜景处理成长曝光式动态摄影。
- 云层缓慢流动，塔灯和城市灯光进行低频、不规则微闪。
- 水面倒影纵向扰动，底部光轨缓慢延伸。
- 该主题表达“照片被重新唤醒”，不恢复旧版翻页相册叙事。

## 5. Option Wheel

使用 React Bits 官方 `OptionWheel` 的 JS + CSS 版本。当前官方组件无额外依赖，支持鼠标滚轮、拖拽、方向键、左右对齐、曲线、倾斜、模糊、透明衰减与吸附。

视觉与交互要求：

- 放在屏幕内右侧，使用 `side="right"`。
- 当前主题完整高亮；上下相邻主题保留弧形、模糊和透明衰减。
- `items` 使用 `F1 / M4 / COLNAGO / FISH / PHOTO`。
- 非当前项点击只改变选择，不直接跳转。
- 鼠标滚轮和触控板连续跟手；停止约 `140ms` 后吸附到最近主题。
- 移动端支持纵向拖拽。

官方组件只通过 `onChange` 暴露吸附后的索引，不暴露连续位置。为满足场景与滚轮的连续联动，允许在保留官方运动算法和结构的前提下做最小扩展：增加连续位置回调，例如 `onPositionChange(position)`。该回调只上报内部平滑位置，不改变原组件的选择、拖拽、键盘与无障碍逻辑。

## 6. Specular Button

使用 React Bits 官方 `SpecularButton` 的 JS + CSS 版本，并安装其官方依赖 `ogl`。

- 位于屏幕中央下方。
- 文案随主题变化：`ENTER F1 / ENTER M4 / ENTER COLNAGO / ENTER FISH / ENTER PHOTO`。
- 按钮是进入专题页的唯一主操作。
- 默认保持低强度自动扫光，使按钮在没有指针活动时仍可识别。
- 鼠标进入接近范围后，高光转为跟随指针。
- 点击时使用组件自带的小幅缩放反馈。
- 在五张明暗差异明显的照片上都必须保持文字和轮廓可读。

## 7. 连续主题过渡

Option Wheel 的连续位置是唯一主题进度源。相邻主题之间同步驱动：

- 照片场景带的纵向位置和视差。
- 巨型背景字的纵向交接。
- 屏幕外哑光背景色插值。
- 屏幕内主色遮罩和玻璃反射强度。
- 当前与相邻主题动态层的启停。

滚动过程中不使用离散硬切。停止后才吸附到主题锚点，并更新 Specular Button 文案和目标路由。

## 8. 组件边界

- `Home`：主页编排、当前主题索引、路由进入。
- `LaptopStage`：台面、设备外壳、共享透视、接触阴影、指针视差。
- `ScreenExperience`：屏幕安全区、场景带、巨型字和色彩过渡。
- `PhotoMotionScene`：照片分层的统一接口；每个主题提供独立配置和动态绘制函数。
- `OptionWheel`：从 React Bits 官方源码导入并做连续位置的最小扩展。
- `SpecularButton`：从 React Bits 官方源码导入，处理唯一的专题进入操作。
- `themeMeta`：主题顺序、路由、照片导入、主色、裁切焦点、巨型字和动态参数。

组件应保持单一职责。照片动效不得重新塞回 `Home.jsx`，设备 3D 与主题内容也不得共用一组难以拆分的 DOM 写入逻辑。

## 9. 动画与性能

- 使用 GSAP ticker 或统一 RAF 驱动连续动画。
- 设备指针视差使用 `gsap.quickTo()`，避免每次指针移动创建新 tween。
- 高频位移仅写入 `transform`、`opacity` 和必要的 CSS 自定义属性。
- React state 只保存吸附后的当前主题；连续滚动位置和渲染状态使用 ref。
- 当前主题运行完整动态，相邻主题只运行过渡所需图层，其余主题暂停。
- 预加载当前和相邻照片，其他照片延迟加载。
- 五张原图生成适合网页的优化版本；超大原图不直接常驻解码。
- `F1` 与 `COLNAGO` 使用通过视觉验收的 2× 超分衍生图；其他图片只在实际存在压缩或清晰度问题时修复。
- 颗粒、烟雾、焦散等效果共享少量渲染循环，避免大量独立定时器。
- 图片加载失败时显示该主题的哑光主色与巨型字，Option Wheel 与进入按钮仍可使用。

## 10. 响应式与无障碍

桌面端为主要展示目标。移动端采用独立适配：

- 减少设备偏转角和前景机身高度。
- 缩小 Option Wheel，并扩大其实际拖拽命中区。
- 减少照片分层、粒子和背景滤镜，不移除主题选择和进入功能。
- 为每张照片设置独立裁切焦点，确保主体在桌面宽屏、普通笔记本和移动端都可见。

键盘支持：

- 上下或左右方向键切换主题。
- Enter 在主题吸附后进入对应专题。
- Option Wheel 和按钮保留清晰的 `focus-visible` 样式。

`prefers-reduced-motion` 下：

- 关闭设备指针视差、持续烟雾扩散、焦散、粒子和持续扫光。
- 主题切换降级为短距离位移与淡入淡出。
- 保留键盘、拖拽和跳转能力。

## 11. 验收标准

1. 笔记本外壳与屏幕内容共享真实透视，不出现斜框内的正面贴图错位。
2. 五张照片均从项目资产导入；删除桌面 `1111` 文件夹后仍可运行和构建。
3. `F1` 与 `COLNAGO` 的 2× 超分结果通过原图对照检查，不出现品牌、器材、人物或边缘结构的 AI 错绘。
4. 五个主题在桌面、普通笔记本和移动端均不会裁掉核心主体。
5. Option Wheel 在鼠标滚轮、触控板、拖拽和键盘下准确吸附。
6. 照片、巨型字和背景色与 Option Wheel 连续同步，无白屏、闪烁或颜色跳变。
7. Specular Button 是唯一进入入口，五个主题下始终可读。
8. 隐藏主题停止高成本动画，主页在目标设备上保持平滑。
9. 减少动态偏好下不运行持续动效。
10. `npm run build` 必须通过。
11. 分别截取 `F1 / M4 / COLNAGO / FISH / PHOTO` 五张主页截图，检查透视、裁切、文字、按钮、Option Wheel 与背景融合。

## 12. 范围边界

本规格只重做主页 `/`。五个专题页的内容结构和视觉设计不在本轮重做范围内，但主页按钮仍使用现有路由进入它们。现有主页的程序化 Canvas 场景、实体滚轮外观和旧滚轮相关样式将在实现阶段被替换或移除。
